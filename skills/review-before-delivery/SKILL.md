# 渡す前の点検（ガードレール）

人に指摘されてから直すのをやめる。文があふれる、短すぎて伝わらない、凡例と線がずれる、といったことは、自分で見つけられる。
図や文書を人に渡す前に、この手順を必ず通す。途中の版を見せるときも同じ。

## 手順

1. **機械の点検を通す。** 見つかった物は全部直す（人の元の文など、わざと残す物は理由を名前に書いて除く）。
   ```bash
   python3 ~/Develop/excel-write/skills/excel-figure/scripts/check_figure.py 図.xlsx
   ```
   ```bash
   python3 ~/Develop/excel-write/skills/review-before-delivery/scripts/check_text.py 文書.md
   ```
   作業場には hook を入れてある。xlsx を書き出したときと Markdown を書いたときに自動で同じ点検が走り、問題があれば知らせてくる。知らせが来たら、直すまで先へ進まない。
2. **Excel で見る。** 確認用の写しを別の名前で開き、拡大して、折り返し・はみ出し・重なりを見る（excel-figure の skill の「確かめ方」）。機械の見積もりは近似なので、最後は実物で見る。
3. **予備知識の無い係に見せる。** 図の画像（文書なら文書そのもの）を、この会話を知らないサブエージェントに渡す。私の結論は渡さない。聞くこと:
   - 一番言いたいことは何か（2 文以内）
   - 何ができない／何が困るのか（指摘ごとに 1 文）
   - 分からない言葉・前提の足りない所・矛盾
   - 文が多すぎる所、逆に短すぎて伝わらない所
   答えが私の言いたいこととずれた所だけを直す。ずれを全部文で埋めない（文を足しすぎると読めなくなる）。まず図の形・並べ方・言葉の選び方で直す。
4. **下の「いつも見る所」を自分で一つずつ見る。** 機械で拾えない物が多い。
5. **人に渡す。** 渡すときは、Excel で確かめたか・予備知識の無い係に見せたかを書く。確かめていないことは、そう書く。

## いつも見る所（人に指摘されたことの一覧）

それぞれ、機械で拾える物には［機械］、自分で見る物には［目］を付けた。

- ［機械］文が箱からあふれていないか。Excel の字は見積もりより広いことがある
- ［機械］凡例に無い線、使っていない凡例、同じ意味なのに違う見た目・違う意味なのに同じ見た目の線が無いか
- ［機械］「読む」線が、読む側（サブエージェント）から読まれる物（計画書・手引き）へ向いているか
- ［機械］線や吹き出しの線が、ほかの箱を横切っていないか
- ［機械］自分で作った言い方（禁止語の一覧）を使っていないか
- ［機械］1 段落・1 文が長すぎないか
- ［目］1 つの指摘が「何が起きるか → 何が困るか」まで書けているか。事実だけで終わっていないか
- ［目］短くしすぎて、肝心の中身（道具の名前・置き場所・誰が何をするか）が抜けていないか
- ［目］同じ物が複数あることが話の芯なら、複数描いているか。番号で区別しているか
- ［目］起こす矢印が、起こす物すべてに届いているか
- ［目］説明の箱が、流れの外に浮いていないか（つながる線が無い箱）
- ［目］その形の前提に無い物を描いていないか（✕ を付けてでも描かない）
- ［目］前の図と番号・言い方・評価（✕ か △ か）が食い違っていないか
- ［目］事実を書きすぎていないか（例: できる手段があるのに「できない」と書いていないか）
- ［目］人がぱっと見て、10 秒で一番言いたいことが分かるか

## 指摘を受けたら（ノウハウを貯める）

人に指摘されたら、直すのと同時に次をする。同じ指摘を二度受けないため。

1. 指摘の種類を一言で名付け、上の「いつも見る所」に足す。
2. 機械で拾えるなら、`check_figure.py` か `check_text.py` に検査を足す。足したら、指摘を受けた版（控え）に当てて、その問題を本当に拾えるか確かめる。
3. 自分で作った言い方を指摘されたら、`banned_words.txt` に、その言い方と代わりの言い方を足す。
4. excel-write にコミットして push する。

## 道具

| 道具 | 役目 |
|---|---|
| `../excel-figure/scripts/check_figure.py` | Excel の図の機械の点検 |
| `scripts/check_text.py` | 文書の機械の点検 |
| `scripts/check_after_tool.py` | hook から呼ぶ点検（xlsx の書き出しと Markdown の書き込みのあと） |
| `banned_words.txt` | 使ってはいけない言い方と、代わりの言い方 |

hook の入れ方（作業場の `.claude/settings.json`）:

```json
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Write|Edit|Bash",
        "hooks": [ { "type": "command",
                     "command": "python3 -B ~/Develop/excel-write/skills/review-before-delivery/scripts/check_after_tool.py" } ] }
    ]
  }
}
```
