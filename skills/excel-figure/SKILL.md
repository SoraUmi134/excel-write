# Excel の説明図を描き足す

人が Excel で描いた説明図の続き（例: パターン 1・2 の横にパターン 3）を、同じ描き方で足す手順。
台本は `scripts/` にある。

| 道具 | 役目 |
|---|---|
| `scripts/xdraw.py` | 図形を組み立てて xlsx に書き込む部品。箱・文字・矢印（箱につなぐ）・吹き出し・✕・＋・まとまり・リンク |
| `scripts/render_drawing.py` | xlsx の図を PNG / SVG に描く。`--list` で図形の種類・位置(pt)・文字を一覧にする |
| `../../examples/gsd-patterns/build_pattern3.py` | 実例 1。人が描いたパターン 1・2 に合わせてパターン 3 を足した台本 |
| `../../examples/gsd-patterns/build_all.py` | 実例 2。人の了承を得て、パターン 1・2 も含めて 3 つを描き直し、計画書と係を複数描いた台本 |

必要な物: python3（標準の部品だけ）、`rsvg-convert`（`brew install librsvg`）。あれば LibreOffice（確かめに使う）。

## 一番大事なこと: 人の描き方に合わせる

前に作った図が「作ってほしい物と違う」と言われた主な理由は、描き方の違いだった。
中身が正しくても、既存の図と並べたときに浮く図は作り直しになる。

- **手順を文章で図に詰め込まない。** 人の図は、矢印の脇の番号（(1) や ①）だけで流れを示す。説明の長文は図に入れない。
- **注意点は「問題点N」の黄色い吹き出し**に赤字で短く書き、該当の箱へ線を出す。根拠は文字で並べず、**参考リンクの札**（下線付きの青字、クリックで該当の一文へ飛ぶ）にする。
- **色で種類を分ける。** 例: GSD の物は薄い緑、方法論独自の物は薄い青、方法論で決める値は赤字、使わない物には ✕。
- **共通の部品は同じ位置に置く。** コマンドの並びやメインのバーなど、前のパターンと同じ物は横位置を揃え、縦だけずらす。

描き始める前に、既存の図から次を読み取って台本の定数にする（実例の台本の先頭を参照）。

1. 描画の道具で既存の図を絵にして見る
   ```bash
   python3 scripts/render_drawing.py 図.xlsx /tmp/今の図.png --scale 0.6
   ```
2. 図形の一覧から、部品の位置・大きさ・文字を拾う
   ```bash
   python3 scripts/render_drawing.py 図.xlsx /tmp/x.svg --list --y0 500 --y1 1250
   ```
3. drawing の XML から、塗り・線・字体・字の大きさ・吹き出しの作り・✕ の作り・リンクの付け方を読む。
   `xl/drawings/drawing1.xml` を開き、代表の図形（箱・矢印・吹き出し・番号・参考リンク）の `spPr` と `rPr` と `xdr:style` を見る。
   「色はテーマの accent6 を 20%＋白 80%」のように、テーマの指定のまま写す（RGB に直すとテーマを変えたときに揃わない）。
4. 矢印がどの箱につながっているか（`a:stCxn` / `a:endCxn`）と、まとまりの入れ子を見る。

## 組み立て方（xdraw.py）

```python
from xdraw import Drawing, write_into
d = Drawing(tag="pattern3", name="パターン3")         # tag は書き直しの目印
a = d.shape(100, 100, 120, 60, "roundRect", fill=("accent6", 20, 80), line=("accent3",),
            adj=8000, text=[[("見出し", {"bold": True})], "名前"], font="Yu Gothic")
b = d.shape(300, 100, 120, 60, "roundRect", ...)
d.connector((a, 3), (b, 1), color=("accent2",), lw=1.5)   # a の右 → b の左 につなぐ
with d.group("問題点1"):                                  # 吹き出しと札を小さなまとまりに
    d.callout(500, 300, 300, 120, ["問題点1", "", "本文"], to=b.site(2))
    d.text(508, 394, 78, 20, "参考リンク1", color=("accent4",), underline=True,
           link="https://…#:~:text=該当の一文", wrap="none")
write_into("元.xlsx", "出力.xlsx", d)                     # 既定でセルに留める
```

- **矢印は箱のつなぎ目につなぐ。** `connector((箱, 番号), (箱, 番号))`。番号は 0=上 1=左 2=下 3=右。つないだ矢印は、人が Excel で箱を動かすと付いてくる。片端だけ箱につなぐこともできる（例: メインのバーの途中から係の箱の上へ。バーのつなぎ目は真ん中にしか無いので、バー側はつながない）。
- **矢印はつなぎ目の位置から引く。** つなぎ目と違う所から引くと、Excel が開いたときや箱を動かしたときに矢印が跳ぶ。真っすぐにしたいときは、箱の中心をつなぎ目に揃えて置く。
- **ホームベース（homePlate）の上下のつなぎ目は、真ん中ではない。** 矢じりの部分を除いた四角の真ん中にある。`shape.site(2)` で位置を取ってから、下の箱をそこに揃える。
- **まとまり。** 足す図形は全体で 1 つのまとまりになる。その中で、一緒に動かしたい物（吹き出しと参考リンクの札、係の箱と追加の説明の箱、✕ と消す箱）は `with d.group(名前):` で小さなまとまりにする。
- **書き直し。** 同じ `tag` で `write_into` すると、前に足したまとまりとそのリンクを消してから足す。人の図には触らない。

## 1 つずつ描くと伝わらない話は、複数を描く

「計画書ごとに係を選べない」のように、**同じ物が何個もあることが話の芯**なら、1 個だけ描いた図では伝わらない（人の図で実際に起きた）。

- 種類が違う物を 3 段ほど縦に並べる（例: read・build・vrt の工程の計画書）。各段で、何が起きるか（どの係が起きるか）を横に並べて比べられるようにする。
- 「同じ種類が画面の数だけある」は、重なったカード（`stack`。後ろに 2 枚ずらして重ねる）で示す。
- 比べるパターン同士は、段の並びと横位置を揃える。並べて見たときに「ここが違う」が目で分かる。
- 実物の名前を使う。キットの係の名前や工程の語は、手引きや係のファイルから確かめてから書く。

## 人の図に手を入れてよいと言われたとき

人の図を残したまま部品を足すと、段を増やす余地が足りないことが多い。了承をもらったうえで、人の図も台本で描き直す。

1. **文字とリンクを読み出してそのまま移す。** 図形ごとの文字・色・リンク先を一覧にし（`render_drawing.py` の描き方を使って書き出す）、吹き出しの本文や参考リンクは一字も変えずに台本へ写す。直したのは並べ方だけ、にする。
2. **外す前にセルの大きさを測る。** `grid = measure_grid(元.xlsx)`。人の図を外すと測る物が無くなる。
3. **書き込むときに人の図を外す。** `write_into(元, 出力, [d1, d2, d3], grid=grid, replace_hand_drawn=True)`。目印（tag）の無い図が外れる。
4. **セルに入ったラベルにも気を付ける。** 人は図の横のセルに文字を書いて、図の一部として使っていることがある（例: `./claude/agents/〇〇.md`）。図の中の文字に移し、セルは `sheet_edit` で空にする。「以上」のような区切りの文字は、最後の図の下へ動かす。

## 書き込み（セルに留める）

人が Excel で描いた図は「どのセルからどのセルまで」で留まっている（twoCellAnchor）。
足す図を「何 pt の位置」で留める（absoluteAnchor）と、Excel 以外のアプリでは人の図と大きさがずれる。
LibreOffice では人の図だけ 2 割縮み、足した図だけ大きく見えた。

`write_into` は既定でセルに留める。列の幅と行の高さは、既存の図の「セル番号」と「pt の位置」の両方から測る。
設定の値から計算しない。理由は、Mac の Excel が行の高さ 20pt を 20.45pt として留めていたため。
測れる図が無いときだけ位置で留める。

## 確かめ方（Excel がある Mac）

Excel で確かめるのが一番確か。人が開いているファイルには触らず、**確認用の写し**を別の名前で開く。

```bash
open -g -a "Microsoft Excel" 確認用.xlsx
```

- **図形の種類を Excel に聞く。** 「図（画像）になっていないか」「グループになっているか」が分かる。
  ```bash
  osascript -e 'tell application "Microsoft Excel" to get name of every workbook'
  ```
  ```applescript
  tell application "Microsoft Excel"
    set ws to active sheet of workbook "確認用.xlsx"
    repeat with i from 1 to count of shapes of ws
      log (name of shape i of ws) & " " & ((shape type of shape i of ws) as string)
    end repeat
  end tell
  ```
  画像なら `shape type picture`、グループなら `shape type group`、ふつうの図形なら `shape type auto` と出る。
- **見た目は窓の画面を撮って見る**（computer-use の app_screenshot）。表示の位置は `set scroll row of active window to 行番号` で送る。窓が別の画面（Space）にあると、クリックとスクロールは届かないが、画面を撮ることと AppleScript は使える。
- **Excel の字は、自前の描画の見込みより広い。** Yu Gothic の太字は特に広く、見込みでは収まった箱が Excel では折り返した。箱の幅は見込みより 1〜2 割広く取り、Excel で拡大（app_zoom）して折り返しを確かめる。
- 確かめ終わったら、写しを保存せずに閉じる: `close workbook "確認用.xlsx" saving no`。

## 確かめ方（Excel が無い Mac）

1. **自前の描画で全体を見る**: `render_drawing.py 出力.xlsx 確認.png`。配置・重なり・はみ出し・吹き出しの線が他の箱をかすめていないか。字の幅は近似。
2. **XML の形**: `python3 -c "import zipfile,xml.dom.minidom as m; m.parseString(zipfile.ZipFile('出力.xlsx').read('xl/drawings/drawing1.xml'))"`
3. **人の図が残っているか**: 元の drawing の `</xdr:wsDr>` の前までが、出力の頭とそっくり同じか。変わった部品が drawing と その rels だけか。
4. **別のアプリで見る**: LibreOffice で PDF にする。シートが何頁にも割れるので、**確認用の写し**だけ「1 頁に収める」設定にする（`<sheetPr><pageSetUpPr fitToPage="1"/></sheetPr>` と `<pageSetup fitToWidth="1" fitToHeight="1"/>`）。人の設定を汚さないよう、設定のフォルダは作業用に分ける。
   ```bash
   /Applications/LibreOffice.app/Contents/MacOS/soffice -env:UserInstallation=file:///作業用/profile \
     --headless --convert-to pdf --outdir 出力先 確認用.xlsx
   ```
   LibreOffice の PDF では日本語の字が抜けることがある（字体の都合）。形・色・線・つながりを見るのに使う。
5. Numbers でも開ける。`wrap="none"`（折り返さない）は Numbers が無視して折り返すので、見出しも箱は十分に広く取る。
6. 最後は人に Excel で開いてもらう。Excel で確かめていないことは、そうはっきり伝える。

## 置き換えるときの注意

- 置き換える前に、ファイルが前に読んだときから変わっていないか確かめる（drawing を比べる）。人が手で直していたら、その版を土台にする。
- 置き換える前に、今の版の控えを作業用のフォルダに取る。
- **人が Excel で開いているファイルは置き換えない。** 同じフォルダに `~$ファイル名.xlsx` という小さなファイルがあれば、Excel で開いている印。置き換えても、人が保存すると上書きし合う。新しい名前で置き、そう伝える。
- 「図形が全部、図（画像）になっていて操作できない」と言われたら、まず何で開いているかを確かめる。Excel が無い Mac で、Finder のプレビュー（スペースキー）や添付の表示で開くと、図全体が 1 枚の絵として見え、何も選べない。Excel で開けば選べる。
- グループの中の図形は、Excel では 1 回目のクリックでグループ全体、もう 1 回で中の図形が選ばれる。動かしにくいと言われたら、このことを伝える。

## 細かい落とし穴

- **吹き出し（borderCallout1）の線**: `adj1`=線の始まりの縦位置、`adj2`=横位置、`adj3`=線の先の縦位置、`adj4`=横位置。どれも吹き出しの箱に対する割合 ×100000。`callout(..., to=(x, y))` が計算する。線が他の箱をかすめやすいので、絵で必ず見る。
- **十字形（plus）の `adj`** は「辺から腕までの距離」。大きいほど腕が細い。人の ✕ は adj 45833 を約 313 度回した物だった。
- **ハイパーリンク**は図形の `cNvPr` の中に `<a:hlinkClick r:id="…"/>` を置き、drawing の rels に `TargetMode="External"` の行を足す。r の名前空間は要素ごとに書けば根元に要らない。rels の Id は既存と重ねない。
- **該当の一文へ飛ぶリンク**は `#:~:text=` を使う。GitHub の markdown は太字や `コード` の記号が消えた状態で照合されるので、記号を含まない一続きの文を選ぶ。今の main の文面で、その文が本当にあるか確かめてから使う。
- **線の太さ**: 人の矢印が太さを持たず `xdr:style` の線の型（lnRef idx）に頼っているときは、テーマの `a:lnStyleLst` の該当の太さを読んで同じ太さにする（今回は 2 番 = 1.5pt）。
- **字体**: 人の図の字体を写す（今回は箱が Yu Gothic、ラベルと吹き出しが BIZ UDGothic、見出しと番号はテーマの既定）。
